# Contributing

Keep additions practical and testable.

## Good additions

- a command that answers a real troubleshooting question;
- a small safe lab;
- an explanation of why a control matters;
- a production caveat;
- a primary-source reference;
- a “what I would check next” section.

## Avoid

- copy-pasted vendor manuals;
- exploit instructions against real targets;
- commands that destroy logs or evidence without an explicit warning;
- secrets, credentials, or personal data;
- claims that a single hardening command makes a host secure.

Write like an engineer leaving notes for the next engineer on call.
